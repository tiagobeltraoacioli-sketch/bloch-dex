# DEX testnet recovery evidence

The original chain 84001 RPC is unavailable. Its primary Anvil state file is
empty and its disk exhausted. The already-failing Anvil unit was stopped to
end its restart loop; the source state and cache were preserved.

The latest valid cached snapshot has SHA256
`2e9229091108c872297374a0d85633c85784b63fbb89dd096b233f08fa3671e5`.
Its highest recorded block is 59887, hash
`0xab9e21e70598398d818f541e9ac86f0bc5635eec107fa7224c51d9a7d3cf3f2e`.
The previous snapshot's accounts and storage are semantically identical.

The recovery converter and offline verifier checked 21 accounts, 173 storage
slots and the runtime hashes of 16 contracts against the published deployment
record, using the original Anvil 1.7.1 build (commit `4072e487`). The isolated
process generated no accounts, mined no blocks and has been stopped.

These cache snapshots contain accounts, storage and block hashes. They do not
contain the original block headers, transactions, receipts or block execution
environment. Importing recovered accounts produces a different genesis at block
zero. Matching account data and a cached original genesis hash do not restore
chain continuity or prove that no later state was lost.

Do not promote this account export as the existing chain or replace the public
deployment configuration. A complete state backup is still needed for restoration;
otherwise a separate decision must approve a new testnet and its history loss.
Chain 8400 is an older, different runtime and is not a failover for 84001.

Recovery data and operational inventories remain outside Git. The converter's
tests cover malformed snapshot handling; the offline comparison provides the
additional evidence above. Backups of these artifacts preserve recovery evidence,
not a fully restorable chain.
