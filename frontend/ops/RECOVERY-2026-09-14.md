# DEX testnet recovery evidence

The original chain 84001 RPC became unavailable. Its primary Anvil state file was
empty and its disk exhausted. The already-failing Anvil unit was stopped to
end its restart loop; the source state and cache were preserved.

The latest valid cached snapshot has SHA256
`2e9229091108c872297374a0d85633c85784b63fbb89dd096b233f08fa3671e5`.
Its highest recorded block is 59887, hash
`0xab9e21e70598398d818f541e9ac86f0bc5635eec107fa7224c51d9a7d3cf3f2e`.
The previous snapshot's accounts and storage are semantically identical.

The recovery converter and offline verifier checked 21 accounts, 173 storage
slots and the runtime hashes of 16 contracts against the published deployment
record, using the original Anvil 1.7.1 build (commit `4072e487`). The isolated
process generated no accounts, mined no blocks and has been stopped.

These cache snapshots contain accounts, storage and block hashes. They do not
contain the original block headers, transactions, receipts or block execution
environment. Importing recovered accounts produces a different genesis at block
zero. Matching account data and a cached original genesis hash do not restore
chain continuity or prove that no later state was lost.

The account export cannot restore the original chain's history. A complete state
backup would have been required for that restoration; otherwise a separate
decision had to approve a new testnet and its history loss.
Chain 8400 is an older, different runtime and is not a failover for 84001.

Recovery data and operational inventories remain outside Git. The converter's
tests cover malformed snapshot handling; the offline comparison provides the
additional evidence above. Backups of these artifacts preserve recovery evidence,
not a fully restorable chain.

A complete archive of the remaining source directory was subsequently captured
off-host and fully decompressed locally. All 3,602 regular members were read and
hashed (16,559,212,832 uncompressed bytes), including the known valid snapshot.
The compressed archive SHA256 is
`6d7a2c41e350850c9e7cd83cb4fd9584c61b115abd143190fad3212e38b2fab2`.
Its private member manifest is stored beside the archive outside Git. This
preserves the surviving directory; it does not replace the missing chain dump.
Incomplete earlier transfers are marked `.partial` and are not verified backups.

## Authorized testnet relaunch

The operator subsequently confirmed that no user transactions or bridge deposits
needed preservation and explicitly authorized relaunching the testnet. The new
runtime retains chain ID 84001 and the recovered contract addresses, with new
genesis `0x81e8a274272183bd17f71ece585d03bb7c74d82bd3e7a03b396182c1b0d56edf`.
It is a new testnet history, not a restoration of the old history.

The recovered 21 accounts and 173 storage slots were compared against the live
local runtime before publishing its identity. The reviewed frontend adapter
changes the embedded genesis and deployment JSON under exact original asset
SHA256 pins, and changes the bundle URL to avoid cached old configuration.

After both complete archives matched, only the 3,600 archived cache files were
removed to recover about 16 GB of disk space. The empty original state and faucet
database remain in their original directory. The new runtime uses a separate
data directory, transaction-triggered mining, bounded in-memory state history
and no historical state cache on disk. Atomic checkpoints are a separate service.
