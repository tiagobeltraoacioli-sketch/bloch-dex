# Authorized DEX testnet relaunch

The operator authorized a fresh testnet history after confirming that no user
transaction history or bridge deposits needed preservation. The recovered
contract addresses remain in use on experimental chain 84001; this does not
activate native Bloch L1 settlement or a USDT bridge.

The new verified genesis is
`0x81e8a274272183bd17f71ece585d03bb7c74d82bd3e7a03b396182c1b0d56edf`.
The original genesis remains documented in `recovery-2026-09-14.json`.
The primary's 21 recovered accounts and 173 storage slots were checked before
publication. The public deployment JSON was then checked to differ only in
genesis; factory, router, tokens, pools and runtime-code pins remain unchanged.

Published Worker `blochdex-mobile-wallet` version:
`a8b99f52-5781-46b6-a3f9-4e2665e8a55a`.
The existing Pages application and API handlers remain the underlying origin.
The adapter validates original JavaScript and JSON hashes before replacing the
single genesis literal and forces a fresh bundle URL for previously cached
browsers. It preserves the MetaMask mobile handoff module.

Reproduce the selected adapter from `frontend/` with Node 24:

```sh
POSTERN_RECOVERY_ARTIFACT=edge/recovery-2026-09-14.json npm run build:mobile-hotfix
```

Validation included all seven edge tests against captured production assets,
the existing 47 frontend tests and build, and WebKit/iPhone 13 checks against
both the recovered captured app and the published site. MetaMask handoff,
delayed provider injection, explicit mock authorization and disconnect passed
with no page errors. Browser tests use mock providers and intercept fund-moving
requests; they do not prove physical-iPhone app authorization or execute swaps.

The public RPC subsequently passed chain/genesis checks, all 16 runtime-code
hashes and all seven factory-pair identities. Pools have positive test reserves.
Read-only router quotes work between tBLCH and tUSDT through tUSDC; no direct
tBLCH/tUSDT pair exists in this deployment. These are test ERC-20 assets, not a
native L1 BLCH/USDT pool. No public transactions or faucet requests were sent
during these checks.

The checkpoint service passed a real isolated Anvil test with one disposable
zero-value self-transfer: full state, genesis and receipt survived a restart.
The actual primary also passed a full-state restart comparison. The checkpoint
test transaction never reached the public network.

See `../ops/RECOVERY-2026-09-14.md` for the verified original backups, authorized
cache cleanup and separate recovered runtime. Checkpoints preserve full current
state atomically; they do not reconstitute the discarded original history.
